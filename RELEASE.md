# Releases

Each section is the body of its GitHub release (`scripts/release-notes.sh`).
A release is a pushed tag `vX.Y.Z` equal to `interop_version` in
versions.yaml: the Release workflow builds and self-tests every image
natively on amd64 and arm64, pushes `<image>:vX.Y.Z-<arch>`, joins them into
the multi-arch `<image>:vX.Y.Z` and publishes the release with the digests.

## v0.5.0

**Date:** 2026-10-28
**Previous release:** v0.4.0

Container contract 1.3: additions only, every v0.4.0 consumer keeps working.

* **CAN XL** (canutils): [frame documents](docs/CONTAINER_CONTRACT.md#frame-document)
  marked `"xl": true` (priority, VCID, SEC and RRS flags, SDT, acceptance
  field, 1..2048 data bytes), `--xl` on `send`, `receive` and `capture`,
  capability `xl`. can-utils v2025.01's cansend and candump carry the frames
  on an interface with the CAN XL MTU, passing VCIDs through; this needs
  Linux ≥ 6.9 (cansend refuses CAN XL interfaces without
  `CAN_RAW_XL_VCID_OPTS`). The other adapters refuse `--xl` as
  `unsupported`.
* **Fixture** `fixtures/frames/xl.jsonl`: six CAN XL frames (priorities 0
  and 0x7FF, SEC and RRS, SDT, AF, VCIDs 0x42 and 0xFF, 1 to 2048 bytes).
* **Self-test suite `xl`**, on `vcanxl0` (mtu 2060, created by `make vcan`):
  the fixture between every pair with the feature, CAN XL frames hidden from
  a receiver without `--xl`, `--xl` on an interface without the CAN XL MTU
  (exit 4), refusal by adapters without the feature (exit 2).
* **canutils receive and capture** count the frames they accept instead of
  using `candump -n`: candump also counts CAN FD and CAN XL frames that a
  receiver without `--fd` or `--xl` drops, so such a receiver could end
  with fewer frames than asked for. candump now runs with `-L` (flushed log
  lines on stdout); `capture` writes the accepted lines.

## v0.4.0

**Date:** 2026-10-28
**Previous release:** v0.3.0

Fixtures only: container contract 1.2 and every image are unchanged in
behaviour (rebuilt and re-tagged).

* **`fixtures/arxml/multiplexed.arxml`**: two `MULTIPLEXED-I-PDU`s — a 4-bit
  Intel selector with a static part and three dynamic alternatives (one
  initial), an 8-bit Motorola selector with two — with decode vectors for
  every selector code plus an undescribed one, and encode vectors.
  Generated by `scripts/gen-arxml-fixtures.py`.
* **Oracle coverage.** cantools 45.1.1 reads multiplexed PDUs (selector
  `<frame>_selector1`, alternatives multiplexed by `SELECTOR-FIELD-CODE`, the
  static part always present); canmatrix 1.3.3 reads only the selector. The
  self-test checks each oracle against three probe frames worked out by
  hand: `arxml-multiplexed-cantools` must pass, `arxml-multiplexed-canmatrix`
  is recorded as known. See docs/FIXTURES.md.
* `scripts/validate-fixtures.py` follows multiplexed PDUs when it checks the
  encode vectors' signal names.

## v0.3.0

**Date:** 2026-10-28
**Previous release:** v0.2.0

Container contract 1.2: additions only, every v0.2.0 consumer keeps working.

* **slcan interfaces** (pythoncan): `send` and `receive` accept `--interface
  slcan:<url>`, python-can 4.6.1's slcan interface (LAWICEL ASCII, the
  protocol of CANable-type serial adapters) over a pyserial URL such as
  `slcan:socket://127.0.0.1:20000`. A consumer plays the adapter on a TCP
  port (go-canbus's slcan transport does) and checks frames both ways
  without a CAN interface. CAN FD as `d`/`D`/`b`/`B` records. slcan has no
  error state indicator, error frames, echo or filters: those requests end
  with exit 2 (`unsupported`). Capability `slcan`.
* The pythoncan image adds pyserial 3.5 (BSD-3-Clause, pinned like every
  package).
* The pythoncanisotp adapter gives its CAN socket a 1 MiB receive buffer:
  a 4095-byte message at STmin 0 (585 frames) overflowed the default one in
  a slow microVM (self-test `mf-4095`, intermittent).
* Self-test suite `slcan`: two python-can slcan clients joined by a TCP
  relay exchange the standard, extended, remote, CAN FD and burst
  fixtures; ESI and error frames are refused.

## v0.2.0

**Date:** 2026-10-28
**Previous release:** v0.1.0

Container contract 1.1: additions only, every v0.1.0 consumer keeps working.

* **`log-convert`** (pythoncan): CAN traces through python-can 4.6.1's own
  readers and writers: Vector ASC, Vector BLF, PEAK TRC, CSV, candump, and
  the contract's frame documents (`.jsonl`, lossless). Capabilities
  `logAsc`, `logBlf`, `logTrc`, `logCsv`. What each format keeps is measured
  in [docs/LOG_FORMATS.md](docs/LOG_FORMATS.md): BLF is lossless; ASC, TRC,
  CSV and python-can's candump writer lose the frame kinds listed there.
  New fixtures `fixtures/logs/`: frames written by python-can as ASC, BLF
  and TRC with python-can's reading of each.
* **ARXML**: cantools and canmatrix decode and encode AUTOSAR 4 ARXML
  (`--db *.arxml`, capability `arxml`), canmatrix converts it to DBC. New
  fixtures `fixtures/arxml/` (generated by `scripts/gen-arxml-fixtures.py`):
  Intel and Motorola signals, standard, extended and CAN FD frames, LINEAR,
  TEXTTABLE, SCALE_LINEAR_AND_TEXTTABLE and IDENTICAL compu methods, signed
  (2C) base types, init values. Both oracles agree on every vector. Neither
  applies a PDU's START-POSITION inside its frame (fixture
  `pdu-offset.arxml`, reported as `known`).
* **Pins**: cantools 45.1.0 → 45.1.1. New weekly Upstream workflow
  (`scripts/latest-upstream.py`): keeps the issue "Upstream releases: pins
  behind the latest" open while a pin or a base image digest is behind;
  never changes a pin.
* **Self-test**: suites `dbc` (now with the ARXML fixtures) and `logs`
  (new). `scripts/chroot-run` runs the exported image file systems with
  chroot where no Docker daemon is, and `scripts/microvm-isotp.sh` runs the
  ISO-TP suite in a virtme-ng microVM with a stock Ubuntu kernel: see
  [TESTING.md](TESTING.md).

Images (multi-arch, linux/amd64 and linux/arm64):
`ghcr.io/otfabric/canbus-interop-{canutils,pythoncan,socketcanrs,scapy,pythoncanisotp,cantools,canmatrix}:v0.2.0`.

## v0.1.0

**Date:** 2026-10-27
**Previous release:** none

First release of canbus-interop.

* Container contract 1.0 ([docs/CONTAINER_CONTRACT.md](docs/CONTAINER_CONTRACT.md)) and JSON Schemas 1.0.
* Images: `canbus-interop-canutils` (can-utils v2025.01; kernel CAN_RAW and
  CAN_ISOTP), `-pythoncan` (python-can 4.6.1), `-socketcanrs` (socketcan
  4.0.0), `-scapy` (Scapy 2.8.0), `-pythoncanisotp` (python-can-isotp 2.0.7),
  `-cantools` (cantools 45.1.0), `-canmatrix` (canmatrix 1.3.3), for
  linux/amd64 and linux/arm64.
* Fixtures: frames (standard, extended, remote, every FD length, ESI, error
  frames, a 2000-frame sequence), seven DBC databases with decode and encode
  vectors, a KCD network.
* Self-test on vcan: raw CAN pairs, filters, loopback, receive-own, error
  frames, multi-consumer, capture/replay, malformed input, interface
  down/up; ISO-TP kernel ↔ python-can-isotp; cantools ↔ canmatrix.
